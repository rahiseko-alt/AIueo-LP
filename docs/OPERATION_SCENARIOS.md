# 権限別 操作シナリオ（オーソドックス50／致命的な危険操作50）

最終更新: 2026-09-09

公開前の横断受入（`IMPLEMENTATION_PLAN.md` P7）で使う操作シナリオ。**すべて現行コードを読んで書いた。想像で足した機能は無い。**

**閲覧用（絞り込みができる）**: https://claude.ai/code/artifact/3ad3f202-9c2a-4ebb-97d6-41deeb496876 ／ 内容はこのファイルと同じで、正本はこちら。

## 権限の区分（実装に対応）

| 記号 | 権限 | 実装上の判定 |
| --- | --- | --- |
| R0 | 未ログイン（参加希望者・通りすがり） | `getAuthContext()` → `signed_out` |
| R1 | ログイン済み・プロフィール未完了 | `profile_missing` または `status='pending_profile'` |
| R2 | 有効会員（企画者） | `member` かつ `status='active'` かつ `role='member'` |
| R3 | 停止・退会会員 | `status='suspended'` / `'withdrawn'` |
| R4 | 管理者 | `status='active'` かつ `role='admin'`（`requireAdmin()`） |
| R5 | システム（Vercel Cron・基盤） | `CRON_SECRET` による Bearer 認証、または基盤未接続時 |

## 判定記号

| 記号 | 意味 |
| --- | --- |
| ✅ | ガードがあり、**自動テストまたは本番実測で確認済み** |
| ⚠️ | コードにガードはあるが、**実DB・実アカウントでの確認が未実施**（開発用DBと運営アカウントが存在しないため） |
| ❌ | **ガードが無い。現状この操作は成立する**、または仕様書の要件が未達 |

| B-47 | サインアウト直後の盗まれたセッションを使う | 最大5分間は有効（`sessionDataTtl: 300`）。ただし `role`/`status` は毎回DBから読むため、**停止措置そのものは即時**に効く。X2として現状維持を決定済み | ⚠️ |
| B-48 | **アプリ用のDB接続文字列が漏洩する** | **全テーブルを直接読み書きできる。** 行レベル権限（RLS）は不採用（2026-09-06に恒久決定）で、認可はサーバー側コードにしか存在しない | ❌ |
| B-49 | **`/api/auth/sign-in/email` へパスワード総当たりを仕掛ける** | **アプリ側の回数制限が無い。** 自前のレート制限は登録APIだけで、ログインは上流 Neon Auth（better-auth）の制限に依存している | ❌ |
| B-50 | cronが二重に実行される | 通知は `dedupe_key` の一意制約で重複しない。状態変更も `for update` と状態条件により冪等 | ⚠️ |

## 使い方

1. **A（オーソドックス）** は、運営アカウントと実企画を用意したあとの通し確認に使う。⚠️ が付いた項目は、実DBで一度も通していないという意味である。
2. **B（危険操作）** は、公開前の敵対検証に使う。❌ が付いた項目は、**現状そのまま公開すると成立してしまう**。修正するか、受け入れるかをユーザーが決める必要がある。
3. 自動化するときは B-01〜B-11 が Playwright で書きやすい（既に一部は `tests/admin-access.spec.ts` `tests/auth-proxy.spec.ts` `tests/registration-endpoint.spec.ts` にある）。R2〜R4 の大半は実DBとログイン状態が要るため、E2Eの前に開発用DBと運営アカウントが必要。
