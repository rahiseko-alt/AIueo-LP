# レスポンシブデザインにおけるブレイクポイント完全ガイド（Framer公式準拠）

本リファレンスは、Framer公式ガイド「Guide to breakpoints in responsive web design」および日本の実務作法に基づいた、レスポンシブWebデザインとブレイクポイント設計の完全手引きです。

---

## 1. ブレイクポイントの基本概念

### ブレイクポイントとは？
- 画面サイズ（ビューポート幅）の変化に応じて、Webサイトのレイアウト・スタイル・コンポーネント構造を切り替える基準点（CSSメディアクエリのトリガー）。
- 単に「スマホ用」「PC用」と切り替えるだけでなく、**「コンテンツが美しく読め、使いやすさが破綻しない境界」**として設計する。

### 一般的な基準値
- **Mobile (Small):** 360px 〜 480px（iPhone SE, Android標準）
- **Mobile (Large / Phablet):** 481px 〜 768px
- **Tablet / Small Laptop:** 769px 〜 1024px（iPad 縦/横）
- **Desktop (Standard):** 1025px 〜 1440px（MacBook, ノートPC）
- **Wide / Large Desktop:** 1441px 〜 1920px+（外部モニター）

---

## 2. 5大設計原則

### 原則1：デバイスではなく「コンテンツ主導」でブレイクポイントを決める
- 特定のiPhoneやMacBookの画面幅に過剰適応させない。
- 「テキストが横に長すぎて読みにくくなった」「カードが狭すぎて改行が崩れた」など、**コンテンツが崩れる瞬間（Natural Breakpoint）**にブレイクポイントを設ける。

### 原則2：リキッド（可変）と固定のハイブリッド
- すべてを固定幅（px）にせず、`%`、`vw`、`clamp()`、`fr` を活用して滑らかに伸縮（Fluid）させる。
- 最大幅（`max-w-[1200px]` 等）を設けて、巨大モニターで横に伸びすぎるのを防ぐ。

### 原則3：タイポグラフィのスケーリング
- デスクトップで `font-size: 4rem` の大見出しは、モバイルでは `font-size: 2rem` や `clamp(2rem, 5vw, 4rem)` で自動調整。
- 1行あたりの文字数は **日本語で35〜45文字、英字で60〜75文字** が最も読みやすい。

### 原則4：タッチターゲットとインタラクション
- モバイル・タブレットでは、タップ可能領域（ボタン・リンク）を **最低 44px × 44px（推奨 48px）** 確保する。
- ホバーエフェクト（`:hover`）に依存した情報開示は避け、タップでも同等の操作ができるようにする。

### 原則5：画像・メディアの最適化
- 画面幅に応じたアスペクト比の調整（デスクトップで横長 16:9 → モバイルで正方形 1:1 や縦長 4:5）。
- `object-fit: cover` や `picture` タグ、Next.js `Image` の `sizes` 設定による高解像度・軽量化。

## 3. レスポンシブ実装チェックリスト

1. [ ] **最小幅テスト**: 360px（iPhone SE等）で横スクロール（はみ出し）が発生していないか？
2. [ ] **中間幅テスト**: 768px〜900px（タブレット縦・折畳み端末）で要素の重なりや文字切れがないか？
3. [ ] **大画面テスト**: 1920px以上のワイド画面でコンテンツが間延びしていないか？（`max-w` の設定）
4. [ ] **ナビゲーション**: 画面幅に応じてハンバーガーメニュー／ドロワーへ自然に切り替わるか？
5. [ ] **グリッドの段組み**: 4列 → 2列 → 1列への折り返しが自然か？
